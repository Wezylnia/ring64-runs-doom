cpu

create a standalone cpu, run the guest toward a stop address, then release the cpu. the quickstart shows how to prepare options.

run-cpu.ts

create and run

loadCpuCompiler(guestMemory?): Promise<WebAssembly.Module>
defaults to memory64 on hosts with wasm memory64 and multi-memory support. other hosts use memory32. pass 'memory32' or 'memory64' to select a profile explicitly. reuse the module across cpus.
createCpu(options: Options): Promise<Cpu>
pass a compiler as wasm bytes or a compiled module, plus limits and a memory configuration. context sets the initial execution mode and segments.
cpu.run(options: RunOptions): Promise<RunResult>
resumes from the current state. read or change state and memory between runs. run options and results describes the budget and stop reasons.

lifecycle

cpu.dispose(): void
releases the cpu. wait for any active run to settle before calling it.
cpu.reset(): void
resets an idle cpu in physical mode and preserves its memory.

interrupts

cpu.requestInterrupt(vector: number): boolean
queues an irq for an idle cpu. use a vector from 0 to 255. returns false if an irq is already queued.
cpu.requestNmi(): void
queues a non-maskable interrupt for an idle cpu.

diagnostics

cpu.inspectTranslations(): UnitMetadata[]
returns a snapshot of the cached translations.
cpu.creationMs: number
cpu creation time in milliseconds.

limits

set all six Limits fields as positive unsigned 32-bit integers. limits apply per vcpu. the quickstart shows a complete set.

maxInstructions, maxSourceBytes
cap the guest instructions and source bytes in one translation.
maxArtifactBytes
caps the bytes in one generated wasm module.
maxCachedArtifacts, maxCachedBytes
cap the module count and total bytes in the translation cache.
maxTranslationsPerRun
bounds translation attempts and retries per run.

run options and results

give cpu.run an instruction budget and an optional stop address. this example reads rax when execution reaches the stop address.

run-to.ts

options

budget: bigint
maximum guest instructions to retire.
stop?: bigint
stop before executing the instruction at this address.
repeatBudget?: bigint
maximum rep iterations. defaults to budget.
eventDelivery?: { budget: bigint }
exceptionDelivery?: { budget: bigint }
enables automatic guest event delivery with a separate budget. pass either spelling.

result fields

RunResult returns a state snapshot. retired and remaining track the instruction budget. repeatIterations and remainingRepeatBudget track the rep budget.

automatic delivery adds deliveryAttempts and remainingDeliveryBudget. resources counts translation and cache work. timings reports milliseconds.

stop reasons

stop, budget, repeat-budget
reached the stop address or used up an execution budget.
event-budget, pending-exception, pending-interrupt
delivery reached its budget or an event is waiting in state.event.
halted, shutdown, paused
guest halt, guest shutdown or a parallel pause.
unsupported, resource-limit
unsupported operation or a translation limit.

fault details

guest faults return results. check reason to find the diagnostic. invalid options and host failures, such as a throwing provider, can reject the run.

fetch-fault, target-fault, data-fault
fault describes the address, access, width and cause.
page-fault
pageFault includes the linear address and guest paging error code.
physical-memory-fault
physicalMemoryFault describes the guest physical access.
segment-fault, protection-fault, system-memory-fault
segmentFault, protectionFault or systemMemoryFault.
alignment-fault, alignment-check, debug-exception
alignmentFault, alignmentCheck or debugException.
simd-exception, x87-exception, general-protection
simdException, x87Exception or generalProtectionFault.
invalid-encoding, device-not-available, divide-error
invalid-encoding can include numericControlFault. device-not-available can include deviceNotAvailable.

memory

copy bytes from a readable linear address to a writable one on an idle cpu.

copy-guest-bytes.ts

memory models

linear
the default. pass code and ram as { base: bigint, bytes: Uint8Array }. execution starts at code.base. code is readable and executable, ram is readable and writable.
ia32e-paged
uses guest page tables in long64 or compatibility mode. pass paging.
physical
maps guest physical addresses. pass context and paging.

read and write

readMemory(address: bigint, length: number): Uint8Array
writeMemory(address: bigint, bytes: Uint8Array): void
access linear mappings. reads return a copy.
readPhysicalMemory(address: bigint, length: number): Uint8Array
writePhysicalMemory(address: bigint, bytes: Uint8Array): void
access guest physical mappings in ia32e-paged or physical. reads return a copy.

on a parallel machine, call shared memory and mapping methods on the machine. they return promises.

backings and mappings

custom linear maps, ia32e-paged and physical require entry, memoryLimits and memory: { backings, mappings }.

MemoryBackingInput
pairs an id with bytes. with memory64, set byteLength to reserve a larger backing. bytes beyond the initial data start at zero.
MemoryMapping
names a backing and supplies base, offset, length and permissions for read, write and execute. mappings must fit their backing and occupy distinct guest ranges.
MemoryLimits
requires maxBackingBytes, maxBackings and maxMappings.
addBacking(input: MemoryBackingInput): void
removeBacking(id: string): void
setMappings(mappings: MemoryMapping[]): void
add bytes, remove an unmapped backing or replace the entire mapping list.

create a machine

loadParallelCompiler(guestMemory?): Promise<WebAssembly.Module>
defaults to memory64 on hosts that support shared wasm memory64. other hosts use memory32. pass 'memory32' or 'memory64' to select a profile explicitly. reuse the module across machines.
createMachine(options: MachineOptions): Promise<Machine>
pass a parallel compiler, limits, memoryModel, memory and memoryLimits. set sharedRamCapacity to a positive multiple of 4096 bytes, allowing for each backing's size rounded up to 4096 bytes.
MachineOptions.cpus
supply at least two records with an entry address. paged and physical cpus need paging. physical cpus also need context.

run and pause

machine.cpus: readonly ParallelCpu[]
each vcpu handle has an id and asynchronous state methods.
cpu.run(options: RunOptions): Promise<ParallelRunResult>
runs one vcpu. the result has the same shape as for a standalone cpu.
cpu.pause(): Promise<void>
machine.pause(): Promise<void>
pause one vcpu or all active runs on the machine. a run that yields returns paused. machine pause waits for outstanding vcpu commands to settle. each command reports its own validation errors.

interrupts

cpu.requestInterrupt(vector: number): Promise<boolean>
cpu.requestNmi(): Promise<void>
queue a maskable or non-maskable interrupt on a vcpu, including during a run.

lifecycle

cpu.reset(): Promise<void>
machine.reset(): Promise<void>
physical mode only. reset one idle vcpu or pause active runs and reset all vcpus. both preserve shared memory. machine reset waits for outstanding vcpu commands to settle before resetting the vcpus.
machine.dispose(): Promise<void>
stops the workers and releases the machine.

port i/o

pass io: portOutput(onByte) to createCpu or createMachine. the provider calls onByte for each byte written to port 0xe9 and returns zero for reads.

port-output.ts

provider callbacks

ports are unsigned 16-bit numbers. IoWidth is 8 | 16 | 32 in bits. callbacks are synchronous and run on the host that created the cpu or machine. return from a callback before calling back into it.

read(port: number, width: IoWidth): number
return an unsigned integer that fits the width.
write(port: number, width: IoWidth, value: number): void
handle the unsigned value and return undefined.

memory-mapped i/o

pass mmio: byteRegister(0xf000n) to createCpu to attach a one-byte device register.

byte-register.ts

address ranges

the mmio option is available on a standalone cpu. ranges lists device regions as { base: bigint, length: number }. use linear addresses in linear mode and guest physical addresses otherwise. ranges occupy slots in maxMappings and must be disjoint from ram and each other.

a naturally aligned scalar mov wholly within one range can call the provider. instruction fetches, host memory methods and other guest memory operations see device addresses as unmapped.

provider callbacks

MmioWidth is 8 | 16 | 32 | 64 in bits. callbacks are synchronous. a throwing provider rejects the run.

read(address: bigint, width: MmioWidth): bigint
return an unsigned bigint that fits the width.
write(address: bigint, width: MmioWidth, value: bigint): void
handle the unsigned bigint and return undefined.
