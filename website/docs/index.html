quickstart

run two x86-64 instructions that add 40 and 2.

npm install ring64

download add.ts and run node add.ts. it prints 42n from rax.

view add.ts
add.ts

if node reports an unknown .ts extension, use node --experimental-strip-types add.ts.

run in a browser

bundle the same add.ts and put both standalone wasm files beside the bundle. the sdk requests the one your browser supports.

terminal 
npx esbuild add.ts --bundle --format=esm \
  --outfile=public/add.js
cp node_modules/ring64/ring64.wasm node_modules/ring64/ring64-memory64.wasm public/

add this to public/index.html.

<script type="module" src="./add.js"></script>

serve public/ over http and open the page. 42n appears in the browser console.

run a binary

pass raw x86 instructions as a Uint8Array in code.bytes. set code.base to the guest address where execution starts.

for an elf or pe file, your app maps its sections and sets up the initial guest state.

example · load a c function

use clang and llvm-objcopy to extract the function's instruction bytes.

add.c
terminal 
clang --target=x86_64-unknown-none-elf -O2 -ffreestanding \
  -fno-stack-protector -fomit-frame-pointer -mno-red-zone \
  -c add.c -o add.o
llvm-objcopy -O binary --only-section=.text add.o add.bin

add-c.ts passes arguments in rdi and rsi and places a return address on the guest stack.

follow the browser steps with add-c.ts and put add.bin beside the bundle. it prints 42n.

parallel example

use createMachine from ring64/parallel to run the same x86-64 addition on two vcpus with different inputs. each vcpu runs in its own worker. both share guest memory.

download parallel.ts and run node parallel.ts. it prints [42n, 12n].

view parallel.ts
parallel.ts

if node reports an unknown .ts extension, use node --experimental-strip-types parallel.ts.

for a browser, see the parallel worker and isolation requirements.
