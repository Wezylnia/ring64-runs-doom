run x86 from typescript

Give a CPU some x86-64 instructions and two numbers. Run it and read the sum from the rax register.

terminal 
npm install ring64
add.mts

On Node.js 22.12 or later, save this as add.mts and run node --experimental-strip-types add.mts. It prints 42n.

code.base is the starting address. stop is the address just past the two instructions. budget caps how many guest instructions can run before control returns to your app.

The example’s limits bound translation work and cache size. See limits when your guest grows beyond this example.

browser setup

Run the example from a TypeScript entry point in a browser with WebAssembly SIMD. loadCpuCompiler() looks for ring64.wasm alongside the SDK. If your bundler moves the SDK, copy node_modules/ring64/ring64.wasm into your public assets and point compiler at it explicitly.

typescript 
const response = await fetch('/ring64.wasm');
if (!response.ok) throw new Error(`could not load ring64.wasm (${response.status})`);
const compiler = new Uint8Array(await response.arrayBuffer());

Pass that compiler to createCpu.

run your own code

The CPU starts at the address you give it. Your app provides the instruction bytes, memory and any state the guest expects. Here is the same addition as a freestanding C function.

add.c

Use Clang and LLVM’s llvm-objcopy to extract the function’s instruction bytes into add.bin.

terminal 
clang --target=x86_64-unknown-none-elf -O2 -ffreestanding \
  -fno-stack-protector -fomit-frame-pointer -mno-red-zone -c add.c -o add.o
llvm-objcopy -O binary --only-section=.text add.o add.bin

Serve add.bin next to the browser script. The x86-64 System V calling convention puts these arguments in rdi and rsi. The host puts a return address on the guest stack, and Ring64 stops there after ret.

memory & i/o

Start with code and ram for a small linear guest. Use backings and mappings when you need more regions or separate read, write and execute permissions. Addresses and register values are bigint. Byte counts are number.

Read registers and memory after a run returns. Keep a long-running guest in a worker if the page needs to stay responsive. An IoProvider connects synchronous guest port reads and writes to your app.

If a device exposes registers at memory addresses, a standalone CPU can route its guest loads and stores to an MMIO provider.

Memory models and mappings cover linear, paged and physical access. Run results explain instruction budgets, normal stops and faults.

parallel

A machine gives each vCPU its own registers and a worker. The vCPUs share guest memory. Here they read the same code, receive different arguments and return [42n, 12n].

parallel.ts

In a browser, serve the page with cross-origin isolation and keep the package’s worker modules and ring64-parallel.wasm available. Parallel execution needs shared memory, atomics and Wasm multiple memories. See the machine API for pause, state and memory access.
