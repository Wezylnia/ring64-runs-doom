cpu limits run & results memory state parallel i/o quickstart

api reference

Import ring64 for a standalone CPU or ring64/parallel for a machine with multiple vCPUs and shared guest memory.

cpu

loadCpuCompiler(): Promise<WebAssembly.Module>
Loads the packaged ring64.wasm. You can reuse the module across CPUs.
createCpu(options: Options): Promise<Cpu>
Takes a compiler as Uint8Array bytes or a compiled module, translation limits and one memory configuration. Use context to set the initial execution mode and io to connect guest ports.
cpu.run(options: RunOptions): Promise<RunResult>
Resumes execution from the current guest state. Read or change state and memory between runs.
cpu.requestInterrupt(vector: number): boolean cpu.requestNmi(): void
Queue an interrupt for the next run. Interrupt vectors range from 0 to 255. requestInterrupt returns false when an IRQ is already queued.
cpu.reset(): void cpu.dispose(): void
In physical mode, reset resets CPU state while preserving memory. Call dispose after the current run has settled to release the CPU.
cpu.inspectTranslations(): UnitMetadata[]
Returns a snapshot of the cached translations.
cpu.creationMs: number
Time spent creating this CPU, in milliseconds.

limits

Supply all six Limits fields as positive 32-bit unsigned integers. Each vCPU has its own translation cache and run limits.

maxInstructions, maxSourceBytes
Cap the instructions and guest source bytes in one translation.
maxArtifactBytes
Caps the size of one generated Wasm module.
maxCachedArtifacts, maxCachedBytes
Cap the count and combined byte size of cached modules.
maxTranslationsPerRun
Caps translation attempts during one run.

The quickstart has a complete limits object. budget controls how many guest instructions retire in a run.

run & results

budget: bigint
The maximum number of guest instructions that can retire in this run.
stop?: bigint
Stop when the instruction pointer reaches this address, before executing it.
repeatBudget?: bigint
Caps REP iterations and defaults to budget.
eventDelivery?: { budget: bigint }
Enables automatic delivery of guest events with its own budget. exceptionDelivery has the same shape. Pass either one.

RunResult returns a reason, a CPU state snapshot, retired and remaining, and repeatIterations and remainingRepeatBudget. Runs with automatic delivery also return deliveryAttempts and remainingDeliveryBudget. resources counts translation and cache work. timings reports phase timings in milliseconds.

stop reasons

Check result.reason before reading its diagnostic. For example, result.pageFault.address is available when the reason is 'page-fault'.

stop, budget, repeat-budget
The CPU reached the stop address or used up one of the run budgets.
event-budget, pending-exception, pending-interrupt
Event delivery reached its limit or an event is waiting in state.event.
halted, shutdown, paused
A guest halt, guest shutdown or a parallel pause request stopped execution.
unsupported, resource-limit
The core could not run the operation or the run hit a translation limit.
fetch-fault, target-fault, data-fault
fault describes the access, its width, address and cause.
page-fault, physical-memory-fault
pageFault reports the guest paging error. physicalMemoryFault reports the failing access to guest physical memory.
segment-fault, protection-fault, system-memory-fault
Read segmentFault, protectionFault or systemMemoryFault.
alignment-fault, alignment-check, debug-exception
Read alignmentFault, alignmentCheck or debugException.
simd-exception, x87-exception, general-protection
Read simdException, x87Exception or generalProtectionFault.
invalid-encoding, device-not-available, divide-error
Instruction or numeric failures. invalid-encoding can include numericControlFault. device-not-available can include deviceNotAvailable.

Guest stops and faults return results. Invalid options and host failures, including a throwing I/O provider, can reject the run.

memory

linear
The default. Pass code and ram spans with { base: bigint, bytes: Uint8Array }. The CPU starts at code.base. The code span is read and execute. The RAM span is read and write. Use explicit memory, entry and memoryLimits for custom mappings.
ia32e-paged
Uses guest page tables in long64 or compatibility mode. Supply explicit memory, an entry address and paging: PagingState.
physical
Maps guest physical addresses. Supply explicit memory, an entry address, context and paging. Use this mode for guests that manage their own execution mode and paging.

A MemoryBackingInput is an id and a Uint8Array of bytes. A MemoryMapping places a backing range at a guest base using a backing ID, byte offset and length, and permissions: { read, write, execute }. Use bigint for addresses and number for byte counts. Mappings must fit their backings and occupy distinct guest address ranges.

MemoryLimits caps the total backing bytes (maxBackingBytes), backing count (maxBackings) and mapping count (maxMappings). Provide all three fields for explicit memory.

readMemory(address: bigint, length: number): Uint8Array writeMemory(address: bigint, bytes: Uint8Array): void
Access a linear mapping. Reads return a copy.
readPhysicalMemory(address: bigint, length: number): Uint8Array writePhysicalMemory(address: bigint, bytes: Uint8Array): void
Access guest physical addresses in ia32e-paged or physical mode. Reads return a copy.
addBacking(input: MemoryBackingInput): void removeBacking(id: string): void setMappings(mappings: MemoryMapping[]): void
Add bytes, remove an unmapped backing or replace the entire mapping list. On a parallel machine these methods and memory reads and writes return promises.

state

readState(): StateSnapshot / setState(state: State): void
Read or set the instruction pointer, flags and the Registers tuple. Its order is rax, rcx, rdx, rbx, rsp, rbp, rsi, rdi, followed by r8 through r15. State also carries interruptibility, pending events and interrupts.
readContext(): ExecutionContextSnapshot / setContext(context: ExecutionContext): void
Read or set execution mode, segmentation and descriptor table state.
readPagingState(): PagingState / setPagingState(state: PagingState): void readFastSystemState(): FastSystemState / setFastSystemState(state: FastSystemState): void
Access paging registers and fast system-call state in a paged or physical CPU. You can supply the initial banks with paging and fastSystem.
readXmmState(): bigint[] / setXmmState(state: bigint[]): void readMxcsr(): number / setMxcsr(value: number): void readX87State(): X87State / setX87State(value: X87State): void
Access the 16 XMM registers, SIMD control and x87 floating-point state.
readDebugState(): DebugState / setDebugState(state: DebugState): void readTimeState(): TimeState / setTimeState(state: TimeState): void readXcr0(): bigint / setXcr0(value: bigint): void readProtectionKeysState(): ProtectionKeysState / setProtectionKeysState(state: ProtectionKeysState): void
Access debug, guest time, extended register control and protection-key state.

parallel

loadParallelCompiler(): Promise<WebAssembly.Module>
Loads the packaged ring64-parallel.wasm for reuse across machines.
createMachine(options: MachineOptions): Promise<Machine>
Pass a parallel compiler, limits, an explicit memoryModel, memory and memoryLimits. Set sharedRamCapacity in bytes as a positive multiple of 4096. Each backing counts toward it rounded up to 4096 bytes.
cpus
Supply at least two CPU records, each with an entry. The paged and physical models also require paging per CPU. Physical mode requires every CPU’s initial context.

The machine creates one dedicated worker per vCPU. The workers share guest memory and hold independent CPU state. Browser use requires a cross-origin isolated page, dedicated workers, shared memory, atomics and Wasm multiple memories.

machine.cpus: readonly ParallelCpu[]
Each handle has an id, async state access and run(options): Promise<ParallelRunResult>. The run result has the same shape as a standalone result. Use the machine for shared memory and mappings.
cpu.pause(): Promise<void> machine.pause(): Promise<void>
Pause the active run on one vCPU or across the machine. A run that yields to a pause returns paused with its saved state and remaining budgets.
cpu.requestInterrupt(vector: number): Promise<boolean> cpu.requestNmi(): Promise<void>
Queue an interrupt on one vCPU. Requests can be made while it runs.
cpu.reset(): Promise<void> machine.reset(): Promise<void> machine.dispose(): Promise<void>
In physical mode, reset one idle vCPU or the entire machine. Dispose the machine to stop its workers and release resources.

i/o

Pass io?: IoProvider to the CPU or machine to handle guest port I/O. The port is a 16-bit unsigned number. IoWidth is 8 | 16 | 32 in bits.

read(port: number, width: IoWidth): number
Return an unsigned integer that fits the requested width.
write(port: number, width: IoWidth, value: number): void
Handle the unsigned value and return undefined.

Both callbacks are synchronous. On a parallel machine they run on the host that created the machine. Return from the callback before calling back into the CPU or machine.

memory-mapped i/o

Pass mmio: MmioProvider to createCpu to reserve device addresses. A range is a base: bigint and a length: number in bytes. Use linear addresses for linear and guest physical addresses for ia32e-paged or physical. Device ranges are separate from RAM mappings and count toward maxMappings.

typescript
import type { MmioProvider } from 'ring64';

let value = 0n;
const mmio = {
  ranges: [{ base: 0x9000n, length: 1 }],
  read() {
    return value;
  },
  write(_address, _width, next) {
    value = next;
  },
} satisfies MmioProvider;

An aligned guest scalar mov through one of these ranges calls read(address, width) or write(address, width, value). Widths are 8 | 16 | 32 | 64 bits. Use unsigned bigint values that fit the width, and return synchronously.

A transaction must fit entirely inside one range. Instruction fetches, host memory access, and guest instructions outside this scalar mov subset see device addresses as unmapped. A throwing provider rejects the run.
